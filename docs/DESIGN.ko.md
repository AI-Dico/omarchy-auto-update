# Auto Update 설계 (초안, 2026-10-20)

오마치 업데이트를 맥처럼 만든다. 내려받기와 검증은 백그라운드에서 조용히 끝내고, 사용자는 동의와 재시작만 한다. 문제가 생기면 업데이트 직전으로 되돌린다.

- 플러그인 id: `io.github.ai-dico.auto-update` (표시 이름 Auto Update / 자동 업데이트)
- 진행 방식: 플러그인으로 실제 기기에서 실증 → 검증된 부분부터 업스트림 제안
- 근거 조사: macOS·Windows·ChromeOS·Android·Fedora·openSUSE·Ubuntu·NixOS·Arch 계열 (`research.ko.md`)

## 1. 원칙

0. **터미널을 열지 않아도 된다.** 오마치를 개발자뿐 아니라 터미널이 두려운 일반 사용자에게도 친숙하게 만든다. 알림·동의·진행·되돌리기는 모두 마우스로 끝나는 화면이어야 하고, 터미널은 문제를 조사할 때만 연다. 윈도우·맥의 업데이트 UX 를 참고하는 이유다.
1. **받기와 바꾸기를 나눈다.** 받기·검증은 사용자 권한 샌드박스에서 한다. 시스템을 바꾸는 일은 동의 뒤 root 로 한 번만 한다.
2. **Arch 는 부분 업그레이드가 금지다.** 일부 패키지만 먼저 올리지 않는다. 등급은 무엇을 올릴지가 아니라 언제 올릴지를 정한다.
3. **받은 그대로 적용한다.** 내려받을 때 쓴 패키지 DB 를 고정해 적용에 그대로 쓴다. 그사이 미러가 바뀌어도 검증한 묶음만 설치된다.
4. **실행 중인 세션의 라이브러리를 바꿔치기하지 않는다.** 셸·Qt·Hyprland·커널이 섞인 묶음은 재시작 때 적용한다.
5. **확정 전에는 아무것도 지우지 않는다.** 업데이트 전 스냅샷은 새 부팅이 확인될 때까지 보존한다.

## 2. 흐름

```
[타이머]  확인 ─▶ 내려받기 ─▶ 검증 ─▶ 준비 완료
                                        │
                     ┌──────────────────┼───────────────────┐
                 조용히 적용          재시작하면 적용        메인 업데이트
                 (동의한 범위)        (알림 → 동의)         (변경 요약 → 동의)
                     │                    │                     │
                 스냅샷 → 설치         스냅샷 → 오프라인 설치 → 재부팅
                     └──────────────────┬───────────────────┘
                                   확정(헬스체크) ─▶ 실패 시 되돌리기 제안
```

### 2.1 확인 (사용자 권한)
- 사용자 systemd 타이머가 6시간마다 실행하고, 부팅 직후에는 10분 뒤 실행한다.
- 시스템과 분리된 DB(`~/.cache/omarchy-auto-update/db`)를 `fakeroot pacman -Sy --dbpath` 로 동기화한다. 로컬 DB 는 읽기 전용 링크다.
- 이렇게 하면 시스템 패키지 DB 를 갱신하지 않으므로 부분 업그레이드 위험이 없다.
- **멈춤 조건**
  - Arch 뉴스에 지난 확인 이후 새 공지가 있으면 자동 적용을 멈추고 "확인 필요"로 둔다. 수동 조치가 필요한 업데이트를 막기 위해서다.
  - 사용자 보류 목록(`IgnorePkg`)과 원격 보류 목록(뒤로 미룸)에 걸린 패키지가 있어도 멈춘다.

### 2.2 내려받기 (사용자 권한)
- 대기 중인 전체 묶음을 `fakeroot pacman -Sw --dbpath <고정 DB> --cachedir ~/.cache/omarchy-auto-update/pkg` 로 받는다.
- **조건**: 계량 연결 아님, 전원 연결 또는 배터리 50% 이상, I/O 우선순위 낮춤(`ionice -c3`, `nice`).
- 끊기면 다음 실행에서 이어받는다.
- 실측(10-20): sudo 없이 받았고, 받는 단계에서 이미 `checking keyring` / `checking package integrity` 를 수행했다.

### 2.3 검증 (사용자 권한)
- 패키지 서명과 해시(pacman 이 받기 단계에서 수행)를 확인한다.
- 의존성 해결을 미리 돌려 본다(`pacman -Su --print --dbpath <고정 DB>`).
- 디스크 여유를 확인한다. 설치 + 스냅샷에 필요한 양이고, 오마치 기준 10 GiB 이다.
- 결과로 `ready.json` 을 남긴다. 담는 것: 묶음 목록, 등급, DB 동기화 시각, 유효기간.

### 2.4 등급 판정 (묶음 전체 기준)

| 등급 | 조건 | 적용 |
|---|---|---|
| 조용히 적용 | 아래 두 목록에 해당하는 패키지가 하나도 없음 | 설정에서 허용한 경우에만, 유휴 시간에 스냅샷 → 설치. 끝나면 알림 한 줄 |
| 재시작하면 적용 | 커널·glibc·systemd·mesa·nvidia·Qt·Quickshell·Hyprland·limine·omarchy 중 하나라도 포함 | 바 알림 "업데이트 준비됨 · 재시작하면 적용". 누르면 동의 1회 → 오프라인 설치 |
| 메인 업데이트 | omarchy 의 major.minor 가 바뀜 (예: 4.0 → 4.5) | 변경 요약(릴리스 노트)을 보여 주고 명시 동의 → 재시작 적용 |

- 10-20 실제 사례: 오마치 4.0.4 → 4.0.6 은 번호로는 패치였지만 Qt 6.11 → 6.12 가 섞여 있었다. 따라서 "재시작하면 적용" 등급이다. 버전 번호가 아니라 묶음 내용으로 판정하는 이유다.

### 2.5 적용 (root, 동의 뒤)
- **공통**: 동의는 polkit GUI 인증으로 마우스로도 할 수 있게 한다(#12348). 적용은 기존 `omarchy update` 경로를 최대한 재사용한다. 재사용할 것은 스냅샷, 공간 검사, 부팅 체인 검증(`omarchy-update-boot`), 마이그레이션이다.
- **조용히 적용**: 스냅샷(설명에 묶음 id) → `pacman -Su --dbpath <고정 DB> --cachedir <캐시>` → 끝.
- **재시작하면 적용**: systemd 오프라인 업데이트 방식이다.
  1. `/system-update` 링크를 만들고 재부팅한다. 부팅하면 `system-update.target` 최소 모드로 들어간다.
  2. 트리거 링크를 먼저 지운다. 재부팅 루프를 막기 위해서다.
  3. 스냅샷 → 설치 → 부팅 체인 검증 → 재부팅. 실패해도 `FailureAction=reboot` 로 빠져나온다.
- **준비물 유효기간**: DB 동기화 후 3일이 지나면 다시 준비한다.
- **질문이 필요한 묶음은 적용하지 않는다.** 충돌 해소나 마이그레이션 확인이 필요하면 "직접 업데이트 필요"로 안내하고 기존 `omarchy update` 를 띄운다.
- **AUR·mise·펌웨어는 범위 밖이다.** 기존 `omarchy update` 에 맡긴다.

### 2.6 확정과 되돌리기
- **확정**: 적용 뒤 첫 로그인에서 헬스체크를 돌린다. 확인 항목은 Hyprland 세션, 셸(Quickshell) 기동, 실패한 systemd 유닛 0개다.
  - 통과하면 "확정"을 기록하고, 이전 스냅샷은 보존 정책에 맡긴다.
  - 실패하면 "업데이트 직전으로 되돌리기" 알림을 띄운다. 버튼을 누르면 `limine-snapper-restore` 로 복원하고 재시작한다.
- **커널이 아예 안 뜨는 경우**: Limine 에 부팅 시도 카운터가 없어 자동 롤백은 불가능하다. 부팅 메뉴의 **Snapshots** 로 수동 복원한다. 적용 전 알림에 이 경로를 한 줄로 안내한다.
- **되돌리기 화면**: 최근 업데이트 묶음 목록(날짜·등급·주요 패키지)을 보여 주고, 하나를 고르면 그 직전 스냅샷으로 복원한다.
- **한계**: 스냅샷 대상은 루트(`/`)뿐이라 홈 폴더는 되돌리지 않는다. 그래서 마이그레이션이 바꾸는 `~/.config` 파일은 적용 전에 따로 백업해 함께 복원한다.

## 3. 알림·연기
- 준비 완료 알림은 바 아이콘 한 개다. 기존 `omarchy.system-update` 자리를 대체하거나 그 옆에 둔다.
- "나중에"를 고르면 24시간 뒤에 다시 알린다. 알림 강도는 단계적으로만 올린다.
- 연기 한도와 강제 재시작은 두지 않는다. 데스크톱 사용자 기기라 강제 재시작은 하지 않는다.
- 쓰는 중(전체 화면·발표·녹화)이면 알림을 미룬다.

## 4. 설정
- 자동 확인·내려받기: 켬(기본).
- 조용히 적용: **끔(기본)**. 켜려면 처음 한 번 동의해야 한다.
- 계량 연결에서 받기: 끔.
- 확인 주기: 6시간.

## 5. 플러그인 구성(예정)

| 파일 | 역할 |
|---|---|
| `bin/omarchy-auto-update` | check / download / verify / classify / status (사용자 권한) |
| `bin/omarchy-auto-update-apply` | 스냅샷·설치·검증 (root, polkit 정책으로만 실행) |
| `systemd/user/*.timer` | 주기 실행 |
| `systemd/system/omarchy-auto-update-offline.service` | system-update.target 에서 오프라인 설치 |
| `BarWidget.qml` / `Panel.qml` | 상태 아이콘·준비 알림·동의·되돌리기 화면 |
| `Service.qml` | 첫 실행 설정 |
| `tests/` | 가짜 미러·가짜 pacman 으로 등급 판정·DB 고정·유효기간·멈춤 조건 시험 |

root 로 설치해야 하는 것은 polkit 정책 1개와 오프라인 서비스 1개다. 썸네일 때처럼 처음 한 번 동의를 받아 설치한다.

## 6. 단계별 실증 계획

1. **확인·내려받기·검증 + 바 알림**: 시스템은 바꾸지 않는다. 받아 두면 기존 `omarchy update` 가 그 캐시를 써서 빨라지는지 실측한다.
2. **재시작하면 적용**: 오프라인 설치·스냅샷·확정 헬스체크. VM 에서 먼저 시험한 뒤 실제 기기에서 실측한다.
3. **되돌리기 화면 + 조용히 적용.**
4. **업스트림 제안**: 1단계(백그라운드 내려받기)부터 이슈 → PR.

## 7. 정할 것
- 바 아이콘: 기존 `omarchy.system-update` 를 대체할지, 따로 둘지.
- 조용히 적용을 처음부터 넣을지, 2단계까지 실증한 뒤 넣을지.
- 원격 보류 목록을 둘지. 운영 부담이 생긴다.
