# Auto Update 설계 (초안, 2026-10-20)

오마치 업데이트를 맥처럼 만든다. 내려받기와 검증은 백그라운드에서 조용히 끝내고, 사용자는 동의와 재시작만 한다. 문제가 생기면 업데이트 직전으로 되돌린다.

- 플러그인 id: `io.github.ai-dico.auto-update` (표시 이름 Auto Update / 자동 업데이트)
- 진행 방식: 플러그인으로 실제 기기에서 실증 → 검증된 부분부터 업스트림 제안
- 근거 조사: macOS·Windows·ChromeOS·Android·Fedora·openSUSE·Ubuntu·NixOS·Arch 계열 (`research.ko.md`)

## 1. 원칙

0. **터미널을 열지 않아도 된다.** 오마치를 개발자뿐 아니라 터미널이 두려운 일반 사용자에게도 친숙하게 만든다. 알림·동의·진행·되돌리기는 모두 마우스로 끝나는 화면이어야 하고, 터미널은 문제를 조사할 때만 연다. 윈도우·맥의 업데이트 UX 를 참고하는 이유다.
1. **받기와 바꾸기를 나눈다.** 받기·검증은 사용자 권한 샌드박스에서 한다. 시스템을 바꾸는 일은 동의 뒤 root 로 한 번만 한다.
2. **Arch 는 부분 업그레이드가 금지다.** 일부 패키지만 먼저 올리지 않는다. 등급은 무엇을 올릴지가 아니라 언제 올릴지를 정한다.
3. **받은 그대로 적용한다.** 내려받을 때 쓴 패키지 DB 를 고정해 적용에 그대로 쓴다. 그사이 미러가 바뀌어도 검증한 묶음만 설치된다.
4. **실행 중인 세션의 라이브러리를 바꿔치기하지 않는다.** 셸·Qt·Hyprland·커널이 섞인 묶음은 재시작 때 적용한다.
5. **확정 전에는 아무것도 지우지 않는다.** 업데이트 전 스냅샷은 새 부팅이 확인될 때까지 보존한다.

## 2. 흐름

```
[타이머]  확인 ─▶ 내려받기 ─▶ 검증 ─▶ 준비 완료
                                        │
                     ┌──────────────────┼───────────────────┐
                 조용히 적용          재시작하면 적용        메인 업데이트
                 (동의한 범위)        (알림 → 동의)         (변경 요약 → 동의)
                     │                    │                     │
                 스냅샷 → 설치         스냅샷 → 오프라인 설치 → 재부팅
                     └──────────────────┬───────────────────┘
                                   확정(헬스체크) ─▶ 실패 시 되돌리기 제안
```

### 2.1 확인 (사용자 권한)
- 사용자 systemd 타이머가 6시간마다 실행하고, 부팅 직후에는 10분 뒤 실행한다.
- 시스템과 분리된 DB(`~/.cache/omarchy-auto-update/db`)를 `fakeroot pacman -Sy --dbpath` 로 동기화한다. 로컬 DB 는 읽기 전용 링크다.
- 이렇게 하면 시스템 패키지 DB 를 갱신하지 않으므로 부분 업그레이드 위험이 없다.
- **멈춤 조건**
  - Arch 뉴스에 지난 확인 이후 새 공지가 있으면 자동 적용을 멈추고 "확인 필요"로 둔다. 수동 조치가 필요한 업데이트를 막기 위해서다.
  - 사용자 보류 목록(`IgnorePkg`)과 원격 보류 목록(뒤로 미룸)에 걸린 패키지가 있어도 멈춘다.

### 2.2 내려받기 (사용자 권한)
- 대기 중인 전체 묶음을 `fakeroot pacman -Sw --dbpath <고정 DB> --cachedir ~/.cache/omarchy-auto-update/pkg` 로 받는다.
- **조건**: 계량 연결 아님, 전원 연결 또는 배터리 50% 이상, I/O 우선순위 낮춤(`ionice -c3`, `nice`).
- 끊기면 다음 실행에서 이어받는다.
- 실측(10-20): sudo 없이 받았고, 받는 단계에서 이미 `checking keyring` / `checking package integrity` 를 수행했다.

### 2.3 검증 (사용자 권한)
- 패키지 서명과 해시(pacman 이 받기 단계에서 수행)를 확인한다.
- 의존성 해결을 미리 돌려 본다(`pacman -Su --print --dbpath <고정 DB>`).
- 디스크 여유를 확인한다. 설치 + 스냅샷에 필요한 양이고, 오마치 기준 10 GiB 이다.
- 결과로 `ready.json` 을 남긴다. 담는 것: 묶음 목록, 등급, DB 동기화 시각, 유효기간.

### 2.4 등급 판정 (묶음 전체 기준)

| 등급 | 조건 | 적용 |
|---|---|---|
| 조용히 적용 | 아래 두 목록에 해당하는 패키지가 하나도 없음 | 설정에서 허용한 경우에만, 유휴 시간에 스냅샷 → 설치. 끝나면 알림 한 줄 |
| 재시작하면 적용 | 커널·glibc·systemd·mesa·nvidia·Qt·Quickshell·Hyprland·limine·omarchy 중 하나라도 포함 | 바 알림 "업데이트 준비됨 · 재시작하면 적용". 누르면 동의 1회 → 오프라인 설치 |
| 메인 업데이트 | omarchy 의 major.minor 가 바뀜 (예: 4.0 → 4.5) | 변경 요약(릴리스 노트)을 보여 주고 명시 동의 → 재시작 적용 |

- 10-20 실제 사례: 오마치 4.0.4 → 4.0.6 은 번호로는 패치였지만 Qt 6.11 → 6.12 가 섞여 있었다. 따라서 "재시작하면 적용" 등급이다. 버전 번호가 아니라 묶음 내용으로 판정하는 이유다.

### 2.5 적용 (root, 동의 뒤)
- **공통**: 동의는 비밀번호 창 한 번이다. 1단계와 같은 창을 쓰고, 비밀번호는 진짜 sudo 프롬프트(유효 UID 0 인 sudo 가 터미널을 쥔 상태)에만 입력한다. 오마치에 polkit 인증 창(`omarchy.polkit`)이 들어오면 그쪽으로 옮길 수 있다(#12348).
- **조용히 적용**: 스냅샷(설명에 묶음 id) → `pacman -Su --dbpath <고정 DB> --cachedir <캐시>` → 끝. 3단계.
- **재시작하면 적용** (2단계, 구현: `bin/omarchy-auto-update-offline`): systemd 오프라인 업데이트 방식이다.
  1. **준비** (`stage`, 동의 직후 sudo 로 1회):
     - 모든 저장소가 패키지 서명을 요구하는지 확인한다(`Required`). 아니면 거부한다.
     - root 가 미러에서 DB 를 **직접 새로 받는다**. 사용자 계정이 쓸 수 있는 DB 는 무엇을 설치할지 정하지 못한다.
     - 그 DB 로 묶음을 다시 계획한다. 묶음 지문(전체 트랜잭션의 `이름 버전` 정렬 sha256)이 사용자가 동의한 값과 다르면 멈춘다.
     - 교체(Replaces)·충돌로 설치된 패키지가 지워지는 묶음은 거부하고 기존 `omarchy update` 로 보낸다. 지문에 드러나지 않는 제거이기 때문이다.
     - 사용자 캐시에서는 패키지 파일만 가져온다. 링크를 따라가지 않고 열고, 사용자 소유 일반 파일이어야 하며, DB 가 말하는 크기와 정확히 같아야 한다(복사 중 늘거나 줄면 거부).
     - 패키지는 시스템 캐시(`/var/cache/pacman/pkg`)로 간다. 별도 서브볼륨(@pkg)이라 스냅샷이 패키지를 붙잡지 않는다.
     - 서명을 지금 한 번 검사한다(`pacman -Suw`). 나쁜 파일은 부팅 전에 걸린다.
     - 스크립트와 유닛을 root 만 쓸 수 있는 곳(`/usr/local/libexec/omarchy-auto-update/offline`, `/etc/systemd/system/omarchy-auto-update-offline.service`)에 깔고, `/system-update` 링크를 만든다.
  2. **재시작 중** (`apply`, `system-update.target`):
     - 유닛이 우리 트리거인지 경로 조건으로 확인한다(`/system-update/omarchy-auto-update.json`). 다른 업데이터의 트리거면 건너뛴다. 조건 실패는 재부팅 동작을 부르지 않는다(실측).
     - 스크립트보다 먼저 유닛이 트리거를 지운다(`ExecStartPre`). 재부팅은 유닛의 `SuccessAction`/`FailureAction` 이 한다. Python 이 뜨지 못해도 재부팅 루프가 생기지 않는다.
     - 준비 뒤 3일이 지났거나 그사이 시스템이 바뀌어 지문이 다르면 아무것도 설치하지 않는다.
     - 스냅샷(`snapper --no-dbus`, 설명 `Auto Update <지문 앞 12자>`) → 부팅 메뉴 반영(`limine-snapper-sync`, D-Bus 필요). Snapper 가 있는데 스냅샷이나 메뉴 반영이 실패하면 설치하지 않는다.
     - DB 교체: 현재 DB·서명을 끝까지 써서 백업한 뒤에만 바꾼다. 키링 패키지가 있으면 먼저 설치한다(`omarchy-update-keyring` 과 같은 순서). 그다음 `pacman -Su --noconfirm --cachedir /var/cache/pacman/pkg --overwrite '/usr/share/omarchy/*'`.
     - pacman 이 실패했을 때 설치된 패키지 목록이 그대로면 이전 DB 를 되돌린다. 달라졌으면 「일부 설치」로 기록하고 새 DB 를 둔다. 복원 지점 안내가 함께 나간다.
     - 훅 오류(initramfs·부팅 항목)는 성공으로 숨기지 않고 로그인 뒤 경고 화면으로 띄운다.
     - 설치 전 도구(snapper·limine-snapper-sync·plymouth)는 시간 제한이 있다. pacman 자체는 커밋 중 끊으면 더 위험해서 제한을 두지 않는다.
  3. **로그인 뒤**: 오마치 마이그레이션은 사용자 권한으로 돈다. 그래서 재시작 중에는 못 돌리고 로그인 뒤 자동으로 이어 간다(10-20 사용자 결정). sudo 를 쓰는 마이그레이션이 남아 있을 때만 비밀번호를 묻는다. 실패하면 다음 로그인에 다시 제안한다.
- **신뢰 경계와 남은 위험**: root 헬퍼는 사용자 폴더의 플러그인 파일에서 설치된다. 같은 사용자 권한의 악성코드가 동의 직전에 그 파일을 바꾸면 막을 수 없다(처음 쓸 때 믿는 구조). 실행 중 파일 바꿔치기는 막는다(시작할 때 한 번 읽은 내용을 설치). 근본 해법은 헬퍼를 서명된 패키지로 배포하는 것이다. 비밀번호도 같은 사용자의 다른 프로그램이 같은 가상 터미널을 열어 가로챌 여지가 있어, 오마치 polkit 인증 창으로 옮기는 것이 다음 단계다.
- **준비물 유효기간**: DB 동기화 후 3일이 지나면 다시 준비한다.
- **질문이 필요한 묶음은 적용하지 않는다.** 충돌 해소나 마이그레이션 확인이 필요하면 "직접 업데이트 필요"로 안내하고 기존 `omarchy update` 를 띄운다.
- **AUR·mise·펌웨어는 범위 밖이다.** 기존 `omarchy update` 에 맡긴다.
- **실측(10-20, Try Omarchy VM, btrfs+Limine+snapper)**
  - 3개 묶음, 2개 묶음, 1개 묶음 오프라인 설치가 모두 됐다. 각각 스냅샷 2·3·4 가 생겼고, 4 부터 부팅 메뉴에 올라갔다.
  - 준비 뒤 패키지를 바꾸자 "시스템이 바뀌어 설치하지 않음"으로 넘어갔다. 패키지 DB 도 그대로였다.
  - 발견해 고친 것은 넷이다. 한국어 로케일 sudo 프롬프트를 못 알아봤다(`SUDO_PROMPT` 고정). 자식이 sudo 일 때 터미널 번호를 못 읽었다. 재시작 중 D-Bus 가 없어 부팅 메뉴 반영이 실패했다. root 의 DB 받기가 pacman 7 내려받기 샌드박스(`alpm` 사용자) 때문에 막혔다(임시 폴더 0755).
  - 거부 경로: 캐시의 심볼릭 링크, 잘린 패키지, 다른 지문을 모두 거부했고 남은 파일이 없었다.

### 2.6 확정과 되돌리기
- **확정** (2단계, `omarchy-auto-update after-restart`): 적용 뒤 첫 로그인 45초 뒤에 헬스체크를 돌린다.
  - 확인 항목은 Hyprland 세션, 셸(Quickshell) 기동, 실패한 systemd 유닛(시스템·사용자)이다. 실패 유닛은 동의 직전 목록을 기준으로 **새로 생긴 것만** 센다.
  - 통과하면 마이그레이션을 이어 가고 알림 한 줄로 끝낸다. 이전 스냅샷은 보존 정책에 맡긴다.
  - 실패하면 무엇이 안 떴는지와 되돌리는 길을 보여 준다.
- **되돌리기의 한계**: `limine-snapper-restore` 는 스냅샷으로 부팅한 상태에서만 복원한다. 그래서 켜진 시스템에서 바로 되돌릴 수는 없다.
  - 2단계 안내는 이렇다. 재시작 → 부팅 메뉴 Snapshots → 최신 것 → 뜬 뒤 Restore.
  - 스냅샷이 부팅 메뉴에 못 올라갔으면(`bootMenu: false`) 이 안내를 띄우지 않는다.
- **커널이 아예 안 뜨는 경우**: Limine 에 부팅 시도 카운터가 없어 자동 롤백은 불가능하다. 부팅 메뉴의 **Snapshots** 로 수동 복원한다.
- **되돌려 보기** (3단계 1차, 2026-10-21 desk 실측 통과): 되돌릴 수 있는 동작만 넣었다.
  - 설치 내역 화면(성공 알림을 누르면 열림)과 문제 화면에 「Go back…」을 둔다. 확인 화면을 거쳐 복원 지점으로 **한 번만** 재시작한다.
  - 한 번만 부팅은 Boot Loader Interface 의 `LoaderEntryOneShot` 이다. Limine 이 `LoaderEntries` 에 항목 ID(`Omarchy.Snapshots.6-----2026-10-21-08-50-39.linux-omarchy`)를 알려 준다. logind(`systemctl reboot --boot-loader-entry`)는 BLS 항목만 알아서 Limine 항목을 거부한다(실측). 그래서 `pkexec bootctl set-oneshot <ID>` 로 쓰고 재시작한다. 비밀번호는 오마치 비밀번호 창(polkit)으로 한 번 받는다.
  - 항목은 스냅샷 번호, 설치 시각 ±10분의 날짜, 지금 부팅한 커널 접미가 모두 맞을 때만 고른다(16 과 6 오인 방지).
  - 복원 지점 안에서는 「시험 중」 화면을 띄운다. 업데이트 확인은 멈춘다. 오마치 자체의 터미널 알림(`limine-restore-notify`)은 우리가 시작한 시험 때만 `~/.config/autostart` 의 `Hidden=true` 로 숨기고, 다음 정상 부팅에서 지운다.
  - 돌아오기는 그냥 재시작이다. 오마치 Limine 설정은 기본 항목이 정상 시스템이고 마지막 항목을 기억하지 않는다. 그래도 다시 복원 지점으로 오면 두 번째에는 정상 항목을 이름으로 지정한다(비밀번호).
  - 시험 상태는 `~/.local/state/omarchy-auto-update/rollback.json`(@home)에 둔다. `/var/lib` 은 `/@` 안이라 되돌리면 함께 사라진다.
  - 설치기는 자기 복원 지점을 snapper 정리 대상에서 뺀다(`cleanup ""`, userdata `omarchy-auto-update=yes`). 새로 만들 때 이전 것은 number 정리로 돌려준다.
  - **그대로 두기** (2차, 2026-10-21 Try Omarchy VM 실측 통과): 시험 화면의 「Keep this version…」→ 확인 → 오마치 비밀번호 창 → 재시작.
    - 복원은 Limine 의 것(`limine-snapper-sync --restore --no-mutex`, `RESTORE_METHOD=replace`)을 그대로 쓴다. 지금 `/@` 를 복원 지점 사본으로 바꾸고, 업데이트된 `/@` 는 지우지 않고 새 복원 지점(설명 「The updated version, kept by Auto Update」)으로 부팅 메뉴에 남긴다. 커널도 그 복원 지점의 판으로 되돌린다(커널 업데이트 포함 묶음 실측).
    - 이 도구는 질문 세 개(`Choice [r/l/c]`, 백업 설명, `Reboot now? [Y/n]`)를 줄 편집기로 읽는다. 파이프로는 두 번째 질문에서 CPU 100% 로 멈춘다(실측). 그래서 `pkexec /usr/bin/script -qefc "env LC_ALL=C.UTF-8 … --restore --no-mutex" /dev/null` 로 가상 터미널을 만들고, 헬퍼가 출력을 읽어 질문마다 한 번만 답한다. 복원할 번호가 우리 시험 번호와 다르거나 모르는 질문이 나오면 취소한다. 재시작은 헬퍼가 직접 한다(`n` 으로 답함).
    - 그 뒤 첫 정상 부팅에서 알림 한 번(「Kept the version from before the update」)을 띄운다.
    - 되돌린 묶음은 **더 새 게 나올 때까지 보류**한다(사용자 결정). `~/.local/state/omarchy-auto-update/held.json` 에 `이름 새판` 목록을 두고, 점검한 묶음이 그 안에 다 들어 있으면 상태를 `held`(「N updates on hold」, 「Install again」)로 바꾼다. 하나라도 더 새 판이 있으면 평소처럼 권하고 보류를 끝낸다. 업데이트 기록(`/var/lib/omarchy-auto-update`)은 `/@` 안이라 복원과 함께 되돌아가므로 보류는 @home 에 둔다.
    - 남은 일: 복원 도중 전원 차단은 아직 시험하지 않았다(Limine 의 `mv` 두 번 사이). 작은 화면(800×600)에서 창이 넘쳐 아래 버튼이 잘린다.
  - **남은 위험**: 사용자 권한으로는 `/.snapshots`·`/boot` 를 읽지 못해 대상이 지금도 부팅 가능한지 확인할 수 없다. 항목이 사라졌으면 Limine 이 기본 항목(업데이트된 시스템)으로 부팅하고, 우리는 「복원 지점을 열지 못했다」고 알린다.
- **한계**: 스냅샷 대상은 루트(`/`)뿐이라 홈 폴더는 되돌리지 않는다. 그래서 마이그레이션이 바꾸는 `~/.config` 파일은 적용 전에 따로 백업해 함께 복원한다(3단계).
- **취소**: 재시작 대기 중인 묶음을 화면에서 취소하는 버튼은 아직 없다. 3일이 지나면 저절로 버려지고, 직접 지우려면 `sudo /usr/local/libexec/omarchy-auto-update/offline cancel` 이다(실측 통과).

## 3. 알림·연기
- 준비 완료 알림은 바 아이콘 한 개다. 기존 `omarchy.system-update` 옆에 따로 둔다(§7). 아이콘을 숨기면 데스크톱 알림이 대신한다.
- "나중에"를 고르면 24시간 뒤에 다시 알린다. 알림 강도는 단계적으로만 올린다.
- 연기 한도와 강제 재시작은 두지 않는다. 데스크톱 사용자 기기라 강제 재시작은 하지 않는다.
- 쓰는 중(전체 화면·발표·녹화)이면 알림을 미룬다.

- 조용히 적용: **끔(기본)**. 켜려면 처음 한 번 동의해야 한다.

## 6. 단계별 실증 계획

1. **확인·내려받기·검증 + 바 알림**: 시스템은 바꾸지 않는다. 받아 두면 기존 `omarchy update` 가 그 캐시를 써서 빨라지는지 실측한다.
2. **재시작하면 적용**: 오프라인 설치·스냅샷·확정 헬스체크. VM 실측 완료(10-20), 실제 기기 실측 대기.
3. **되돌리기 화면 + 조용히 적용.**
4. **업스트림 제안**: 1단계(백그라운드 내려받기)부터 이슈 → PR.

    | look | 언제 | 모양 |
    |---|---|---|
    | uptodate | 할 말 없음(Always 에서만 보임) | 불꽃 없는 로켓, 0.45 |
    | checking | 점검 중 | 바 전경색 불꽃 깜빡임, 로켓 0.7 |

    | running | 설치 중 | 노란 불꽃 깜빡임 + 진행 고리(전경 30% 원 + accent 호 회전) |

    | error | 미러 연결 실패 등 | 빨간 경고 삼각형 |

  - 표시 옵션 "Bar icon" 네 단계: `always`(늘 표시, 할 말 없으면 흐린 로켓) · `updates`(기본, 할 말이 있으면 표시. 옛 `shown`) · `important`(재시작 대기·주의·오류·뉴스·실행 중일 때만, 받아 두기만 한 묶음은 숨김) · `hidden`(항상 숨김). 점검 중·받는 중은 사용자가 할 일이 없어 `always` 에서만 보이고, 오류는 주의와 같은 급으로 `updates`·`important` 에서도 보인다. 업데이트 화면의 설정 줄(라벨 아래 4칸)에서 고르고 `~/.config/omarchy-auto-update/config.json` 의 `iconMode` 에 저장한다. 숨겨도 위젯은 바에 남아 `visible` 만 끈다. 점검 타이머가 위젯 안에 있기 때문이다.
  - 숨긴 동안 여는 길: 새 묶음·재시작 대기·주의·새 Arch 뉴스가 생기면 알림 1회(같은 묶음·상태는 다시 알리지 않고, 누르면 업데이트 화면이 열린다). 오마치 메뉴 Update › Auto Update 로도 언제든 연다. 메뉴 항목은 사용자 메뉴 확장 파일의 플러그인 관리 블록이고, 바 위젯이 시작할 때마다 `menu-install --auto` 로 넣는다(사용자가 뺀 뒤에는 다시 넣지 않는다).
  - 남은 위험: 다른 프로그램은 이 잠금을 쓰지 않아 메뉴 파일 교체는 원자적 교환(`mv --exchange`)으로 하고, 확인 뒤 끼어든 쓰기는 되돌려 놓고 다음에 다시 넣는다. 두 교환 사이의 아주 짧은 순간에 들어온 쓰기는 잃을 수 있다.
